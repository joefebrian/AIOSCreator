# Grok Build Execution Prompts

Use the selected Grok Build 0.2.112 session with Grok 4.7 and xhigh. Verify available local configuration rather than copying undocumented CLI flags. These prompts work as ordinary file-based instructions.

## Kickoff

Paste 07_START_GROK_BUILD.txt. It starts repository discovery and staged implementation; the milestone prompts below are useful for a focused continuation, not mandatory permission gates.

~~~text

Map the proposed contracts to actual repository paths. Record existing user changes, verified model/account bindings, available image/voice/ASR/vision capabilities, and the user's benchmark media identity. Identify the smallest safe integration/migration path and feature flag. Preserve unrelated modules and histories.

Write REPOSITORY_DISCOVERY.md, DECISIONS.md, and IMPLEMENTATION_LOG.md under the project handoff directory. Mark unverified items as such. Continue to M1 when reversible implementation is possible. Missing live credentials must not stop independent catalog/UI/contracts work.
~~~


## M3 — Jev and creative planning

~~~text
Implement code-enforced recipe eligibility, pinned Jev 1.13 typed choice, schema validation, context/evidence logging, and explicit EXPLORE versus REUSE_BEST_OBSERVED. No direct media input to Jev. Stage dependent decisions; one question cannot see another new answer in the same call.

Integrate the configured Astra creative role through the existing model service. Generate one selected concept, with fact IDs, actual market/listing/destination, references, one viewer tension, and an executable action. Confidence is not viral/conversion probability. Missing history produces a hypothesis.

Support low-confidence/failed-call recovery and operator recipe overrides within hard constraints. Verify fixture scenarios and actual adapter readiness. Never fabricate a model response or assume a display name is an API ID.
~~~

## M4 — Script and production plan

~~~text
Implement separate semantic beats and camera shots, complete duration coverage, object-state transitions, product/creator/voice locks, approved visual anchors, audio ownership, render grouping, and edit plan.

Validate uncited claims, product actions, age/package information, dialogue timing, actual assets, provider constraints, locale, and offer/destination. Prefer natural current-action speech; prohibit invented personal/child history.

Preview/edit the script and shots in the drawer. Use verified audio previews where available. Calculate costs in code. Persist plan/script approval on the full effective revision hash. Meaningful input changes invalidate dependent approvals. Deliver a complete executable plan, not a prompt-only storyboard.
~~~

## M5 — Real rendering infrastructure

~~~text
Implement durable orchestration, transactional outbox or host equivalent, workers, real provider adapters, account capability checks, bounded candidates/attempts, cost reservations, callbacks/polling, media ingestion, and cancellation/reconciliation.

Use verified Seedance 2.5 and WAN 3.0/Prime bindings. Native audiovisual generation and continuous voiceover are explicit supported strategies. Do not silently change model, locale, voice, or product references.

Test duplicate Generate, worker crash, ambiguous submission acceptance, duplicate callback/poller, late completion after cancel, partial success, budget exhaustion, and workspace isolation. Fixtures must remain visibly labeled. Live calls use explicit generation actions with a reviewed budget; unavailable credentials remain a specific live blocker.
~~~

## M6 — Complete output and benchmark quality

~~~text
Assemble the selected media into a full video with purposeful cuts, coherent sound, actual-audio caption alignment, readable localized text, and verified CTA. Inspect the decoded file and timecoded semantic issues.

Provide final review, per-shot repair, dependency invalidation, exact-output approval, MP4 download, and export manifest. Product/claim/destination errors cannot be hidden by an average QC score.

Run the real pilot protocol through the authorized generation workflow. All five recipes require a real reviewed output to be called validated; all five markets require local-language media checks for full market readiness. Mock outputs and metadata cannot pass this gate. Record media hashes, measured specs, costs/unknown billing, operator scorecards, and any blocked recipe/locale.
~~~

~~~text
Implement manual/CSV performance import against exact final output identity, market, listing, attribution/window, and source. Deduplicate imports, distinguish period totals from cumulative snapshots, preserve nulls/currencies, and compute metrics in code.

Complete relevant E2E, recovery, locale, accessibility, migration, and rollback checks. Ship the operator runbook and report software/live/benchmark/commercial evidence separately. Keep auto-post, ads API automation, payout, and unrelated modules outside this release. Do not publish/deploy without the corresponding authorized workflow.
~~~
